Docker Deployment & Migration

Preparing the MesraMed chatbot environment for a move from a development laptop to a clinic workstation.Menyediakan persekitaran chatbot MesraMed untuk pemindahan daripada laptop pembangunan ke PC klinik.

Data restored · Operational verification pendingData dipulihkan · Pengesahan operasi diperlukan
DockerWSL2Persistent volumesBackup / restore

Deployment contextKonteks deployment

The chatbot environment started on a development laptop using Windows, WSL2 and Docker. Moving it to a clinic workstation required carrying application configuration and WhatsApp session data across, rather than only copying container images.Persekitaran chatbot bermula pada laptop pembangunan menggunakan Windows, WSL2 dan Docker. Pemindahan ke PC klinik memerlukan konfigurasi aplikasi dan data sesi WhatsApp, selain imej container.

What I preparedPersediaan saya

Prepared backups of the n8n_data and waha_sessions volumes, transferred the application images, recreated the Docker network and containers, and restored the data to the destination environment. File ownership was adjusted for n8n after restoration.Menyediakan backup volume n8n_data dan waha_sessions, memindahkan imej aplikasi, menyediakan semula rangkaian Docker dan container serta memulihkan data pada destinasi. Pemilikan fail diselaraskan untuk n8n selepas pemulihan.

Why persistence mattersKepentingan penyimpanan data

Container images hold the application runtime; volumes preserve workflow configuration and session state. Treating these as separate migration items helps retain the working setup when the container or workstation changes.Imej container menyimpan runtime aplikasi; volume mengekalkan konfigurasi workflow dan keadaan sesi. Mengendalikan kedua-duanya sebagai item pemindahan berasingan membantu mengekalkan setup apabila container atau PC berubah.

Remaining operational gatePengesahan operasi seterusnya

The documented restore steps are complete. End-to-end operation after migration still needs confirmation: start the services, reconnect the WhatsApp device if needed, check configuration and webhook uniqueness, then test incoming messages, outgoing replies and staff handover. A completed restore is not presented as proof of continuous uptime.Langkah pemulihan yang didokumentasi telah selesai. Operasi menyeluruh selepas pemindahan masih perlu disahkan: mulakan servis, sambung semula peranti WhatsApp jika perlu, semak konfigurasi dan keunikan webhook, kemudian uji mesej masuk, balasan keluar dan serahan kepada staff. Pemulihan selesai tidak dianggap bukti uptime berterusan.
